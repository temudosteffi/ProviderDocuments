Two code trees differ: the legacy HP.* Oracle schema used integer NUMBER(9,0) IDs with sequences; the current HPP.* schema uses GUIDs (RAW(16)). This document reflects the current state.

2. The 7 Tables

6 EF-mapped tables plus 1 lookup table (CD_EVENT_CATEGORY, accessed by raw SQL, not a DbSet).

erDiagram CD_EVENT_CATEGORY ||--o{ EVENT : "CATEGORY_CD" CD_EVENT_CATEGORY ||--o{ EVENT_SUBSCRIPTION : "CATEGORY_CD" EVENT ||--o{ EVENT_TRACKING : "EVENT_ID" EVENT ||--o{ EVENT_SUBSCRIPTION : "EVENT_ID" SUBSCRIBER ||--o{ EVENT_SUBSCRIPTION : "SUBSCRIBER_ID" NOTIFICATION_AUDIT ||--o{ RECEIVER_AUDIT : "AUDIT_ID"

Two logical groups:

  • Configuration / runtime (who/what/when): CD_EVENT_CATEGORY, EVENT, SUBSCRIBER, EVENT_SUBSCRIPTION, EVENT_TRACKING
  • Audit (what was actually sent): NOTIFICATION_AUDIT, RECEIVER_AUDIT

3. How the Tables Work Together (end to end)

flowchart LR CAT[CD_EVENT_CATEGORY] --> EV[EVENT] EV --> ES[EVENT_SUBSCRIPTION] SUB[SUBSCRIBER] --> ES EV --> ET[EVENT_TRACKING] ES -->|email + optional SMS| SEND{{Delivery}} SEND --> NA[NOTIFICATION_AUDIT] NA --> RA[RECEIVER_AUDIT]
  1. An EVENT is defined (category from CD_EVENT_CATEGORY, optional SLA schedule).
  2. SUBSCRIBERs sign up via EVENT_SUBSCRIPTION (with SEND_SMS flag).
  3. When the event occurs, an EVENT_TRACKING row is written and notifications go out.
  4. Each send is logged in NOTIFICATION_AUDIT, with one RECEIVER_AUDIT row per recipient.

5. Cross-Cutting Conventions

  • GUID PKs on all current tables (RAW(16) Oracle / uniqueidentifier SQL).
  • Standard audit columns on config/runtime tables: IS_ACTIVE, CREATION_TS, LAST_MODIFIED_TS, OPERATOR_ID.
  • Y/N flags stored as fixed-length char(1) (IsFixedLength().IsUnicode(false)).
  • Non-Unicode strings (IsUnicode(false) → varchar, not nvarchar).
  • Dual DB support — identical logical schema maintained in both Oracle and MSSQL script sets, under schema UA3_NOTIFICATIONS.
  • Schema-qualified via EF HasDefaultSchema (default NOTIFICATIONS_WRK, override through DefaultConnectionSchema).
Summary: The UA3_NOTIFICATIONS database holds event definitions, subscribers, their subscriptions, event occurrences, and a two-level send audit — modeled with GUID keys across both Oracle and Azure SQL.
