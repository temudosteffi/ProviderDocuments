2. What it does (simple terms)

A business module (e.g. Program Integrity) sends an event saying "a correspondence letter was generated — please process it." This endpoint receives that event, uses the module's data to render a formatted letter from an SSRS template, puts that letter into an email body, and sends the email to the recipients, writing an audit record of the send.

3. Input / payload

The endpoint accepts an EventMessage carrying a serialized CorrespondenceNotificationGenerated event (namespace HPP.Core.BAS.CQRS.Base.Correspondence.Events). It is mapped internally to AddCorrespondenceNotificationCommand. Key payload fields:

ModuleNameUsed in SSRS template path (e.g. Program Integrity CT)Yes
LetterContentTypeOutput format: PDF/MHTML/HTML4/HTML32/XML/CSV/Image/Excel/Word/ExcelxYes

FromAddress, AddressListSender + To/CC/Bcc recipients—
MailSubject, MailPriorityEmail subject + Normal/High/Low—
AttachmentsFiles from the payload (PDF + Jpeg logo)Optional
Locale, StoreInFileShare, FilePath, FileExtension, NotificationId, DescriptionMetadata—
Envelope: TenantID, ApplicationName, CorrelationId, UserID, UserIpRouting / context—

Wire format is SOAP/HTTP XML with base64-encoded attachments and escaped XmlData.

4. Response

  • The handler Handle(...) returns a new empty Event object — there is no document/URL/status returned to the caller. It is fire-and-forget (render → email → audit).
  • On validation failure (missing ReportName/ModuleName/XmlData/LetterContentType, invalid content type, invalid email): a FaultException<BusinessValidationException> is thrown.
  • On SMTP failure: the audit is still written (with null sent-time), and the exception is rethrown.
  • The REST host wraps errors via ApiExceptionHandlingMiddleware.

5. Implementation (what the handler holds)

CorrespondenceNotificationCommandHandler.Handle (HPP.NotificationServices.Business/CommandHandlers)

  1. Validate via CorrespondenceNotificationValidator.
  2. GenerateReport — builds LetterRequest(TenantId, ApplicationName, "#SSRS.Root/{ModuleName}/Notification Letters/{ReportName}", ModuleName, XmlDocument, {XmlData, ResourcePath}) with SSRS credentials + OutputFormat, then calls CorrespondenceProvider.GenerateCorrespondence(request) → external SSRSProvider (package HPP.Core.API.CorrespondenceManagement) → SSRS server at #RootUrl.RPT/ReportServer/ReportExecution2005.asmx over WCF (SecuredHttpBinding_Standard). Returns LetterResponse.GeneratedDocument (byte[]).
  3. Build body — UTF8.GetString(GeneratedDocument); swap header-logo ContentId if a Jpeg attachment exists.
  4. SendNotification — builds System.Net.Mail.MailMessage (From/To/CC/Bcc, IsBodyHtml if body contains "html", attaches command.Attachments), SmtpClient.Send(message) to the tenant-scoped SMTP server.
  5. Audit — CreateNotifyAuditBusiness(...).Execute().
Config is tenant-scoped (loaded via ApplicationConfigurationManager.LoadApplicationConfiguration(tenantId, RedisCacheManager) → Redis, backed by Azure SQL UA3_TENANT). DI (Autofac) registers the handler, validator, SSRSProvider, and BusinessFactory.

6. Database interaction (in detail)

The only DB write on this path is the audit, done by CreateNotifyAuditDataAccess into the Notifications DB (Oracle or SQL Server, selected by the tenant-scoped DefaultConnectionString):

6.1 NOTIFICATION_AUDIT — one INSERT (raw parameterized SQL)

INSERT INTO NOTIFICATION_AUDIT (AUDIT_ID, FROM_ADDRESS, SUBJECT, MESSAGE, CREATED_TS)
VALUES (@audit_Id, @from_address, @subject, @message, @created_ts)
  • Bind prefix swapped per provider (: Oracle / @ SQL Server) via DbProviderFactories.GetFactory(session.ProviderInvariantName).
  • AUDIT_ID is a new GUID stored as bytes.

6.2 RECEIVER_AUDIT — one INSERT per recipient (Entity Framework)

  • dbcontext.RECEIVER_AUDIT.Add(...) + SaveChanges() for each address.
  • Columns: ReceiverId (new GUID), AuditId (FK), CreationDate (UtcNow), ToAddress, MailType.
There are no reads/writes to EVENT / EVENT_SUBSCRIPTION / SUBSCRIBER tables on the correspondence path — those belong to the event/subscription flows, not correspondence. The letter template and rendering are not in the DB (they live on the SSRS server).
