0. Orientation — What This API Is

  • Project: HPP.BAS.NotificationServicesApi — an ASP.NET Core Web API (net8.0), hosted inside the Service Fabric app HPP.NotificationServices.Main.
  • Single controller: NotificationServiceController inheriting BaseApiController.
  • All endpoints are [HttpPost] (action-name routing) — even the reads. No GET/PUT/DELETE verbs.
  • Thin controller: every action calls the injected INotificationService, implemented by NotificationService.cs.
  • Layering: Controller → NotificationService facade → Business → DataAccess → EF Core (NotificationsDbContext) → UA3_NOTIFICATIONS DB.

1. Authentication & Authorization — IMPORTANT

Finding: there is no authentication, and authorization is effectively a no-op. As written, every endpoint is publicly callable with no token, API key, or role check.
CheckFindingEvidence
AddAuthentication()AbsentStartup.ConfigureServices

UseAuthorization()Present, but no authentication scheme behind itStartup.cs L75
[Authorize] attributesNone on controller or actionsNotificationServiceController.cs
Auth config in appsettingsNone (only ModuleName, ApplicationName, InstrumentationKey)appsettings.json

app.UseAuthorization() without any authentication scheme or [Authorize] attribute does nothing to restrict access. Security currently relies on network/host-level controls (internal Service Fabric networking), not the API itself.

The one gate that exists is tenant validation (not security): every write/send calls InitializeAppConfigManager(tenantId), which throws ArgumentNullException if tenantId is empty and loads that tenant's configuration from Redis cache.

2. Cross-Cutting Behavior (all endpoints)

  • Pipeline: UseHttpsRedirection → UseRouting → ApiExceptionHandlingMiddleware → UseAuthorization → MapControllers. HTTPS enforced.
  • Error handling: each service method wraps logic in try/catch and throws FaultException<ServiceException> via ThrowsException(ex, ExceptionConstants.X); middleware converts to HTTP errors; errors logged via LoggerManager.Logger.LogError.
  • Tenant context: tenantId sets a correlation id + tenant id on the thread cache and loads tenant config.
  • Docs: Swagger/SwaggerUI enabled in Development only.
  • Response shape: reads return Ok(payload) (200 + JSON); DeleteEvent, DeleteSubscriber, SendEmail are void (200/204, no body); errors → fault/problem response.

3. The Endpoints — Grouped by Resource

Routing is action-based: path is effectively POST {base}/NotificationService/{ActionName} with a JSON body.

3A. Events

POST CreateEvent

  • Purpose: Register a new notifiable event definition (name, subsystem, category, message template, optional SLA schedule).
  • Payload: Event — ID (Guid?), Name*, Subsystem*, EventCategory, Description, MessageTemplate, HasSLA, RunsOnMonday…Sunday, RunsOnFirstDayOfMonth, RunsOnLastDayOfMonth, RunsOnThisDayOfMonth (int), RunSchedule, ExpectedRunTimeAs24HHMM, IsActive, OperatorId, TenantId.
  • Operation: new CreateEventBusiness(request).Execute() → CreateEventDataAccess.
  • Tables: EVENT (INSERT).
  • Response: 200 Ok with created Event (ID populated).

POST UpdateEvent

  • Purpose: Modify an existing event definition.
  • Payload: Event (with ID).
  • Operation: businessFactory.CreateUpdateEventBusiness(request).Execute() → UpdateEventDataAccess.
  • Tables: EVENT (UPDATE). Response: 200 Ok updated Event.

POST DeleteEvent

  • Purpose: Logically delete (deactivate) an event.
  • Payload (params): eventId (Guid), userId, tenantId.
  • Operation: CreateDeleteEventBusiness(eventId, userId).Execute() → DeleteEventDataAccess.
  • Tables: EVENT (soft delete — UPDATE IS_ACTIVE). Response: void.

POST GetEvents

  • Purpose: Retrieve events matching simple criteria.
  • Payload: EventSearchCriteria — EventID, Name, Subsystem, Category, HasSLA, IsActive, LocaleCode, TenantId.
  • Operation: new GetEventsBusiness(request).Execute() → GetEventsDataAccess.
  • Tables: EVENT + CD_EVENT_CATEGORY (READ/JOIN). Response: 200 Ok List<Event>.

POST SearchEvents

  • Payload: EventQuery (filters/paging). Operation: TryRoute<EventQuery>(query).
  • Tables: EVENT (+ CD_EVENT_CATEGORY) (READ). Response: 200 Ok EventQuery.

POST GetEventNameDetails

  • Purpose: Distinct event names (dropdowns/filters). Payload: tenantId.
  • Tables: EVENT (READ distinct). Response: 200 Ok List<EventNameDetails>.

3B. Posted Events / Occurrences

POST PostEvent

  • Purpose: Record that an event actually occurred (occurrence), to be notified/tracked.
  • Payload (params): eventName, subsystem, messageBody, isArchivedEvent, processRunTime (DateTime?), previousEventID (Guid?), operatorId, tenantId.
  • Operation: CreatePostedEventBusiness(request).Execute() → CreatePostedEventDataAccess.
  • Tables: EVENT (lookup) + EVENT_TRACKING (INSERT occurrence). Response: 200 Ok PostEvent (PostedEventId, EventPostedTime).

POST GetPostedEvents

  • Payload: PostedEventSearchCriteria — PostedEventId, Name, Subsystem, Message, IsNotified, OccurredAfter/Before, TenantId.
  • Tables: EVENT_TRACKING + EVENT (READ/JOIN). Response: 200 Ok List<PostEvent>.

POST SearchPostedEvents

  • Payload: PostedEventQuery. Operation: TryRoute<PostedEventQuery>. Tables: EVENT_TRACKING (+EVENT) READ. Response: 200 Ok PostedEventQuery.

POST SendAndPostSubscribedEvent composite

  • Purpose: In one call — find subscribers for an event, email them, then record the occurrence.
  • Payload: SendAndPostSubscribedEventCriteria — EventName*, Subsystem*, Subject*, MessageBody*, ToAddress*, FromAddress, OperatorId*, TenantId*.
  • Operation: GetSubscriptionsByEvent() → if any: SendEmail(...) (SMTP) → PostEvent(...).
  • Tables: EVENT_SUBSCRIPTION + SUBSCRIBER + EVENT (read), NOTIFICATION_AUDIT + RECEIVER_AUDIT (audit), EVENT_TRACKING (post). Also SMTP.
  • Response: 200 Ok with PostEvent — null if no subscribers found.

3C. Subscribers

POST CreateSubscriber

  • Purpose: Add a recipient (email + SMS gateway address). Payload: Subscription — SubscriberID, EMail, SmsAddress, OperatorId/UserId, TenantId.
  • Operation: CreateSubscriberBusiness(request).Execute() → CreateSubscribersDataAccess.
  • Tables: SUBSCRIBER (INSERT). Response: 200 Ok Subscription (SubscriberID populated).

POST UpdateSubscriber

  • Tables: SUBSCRIBER (UPDATE). Response: 200 Ok Subscription.

POST DeleteSubscriber

  • Payload (params): subscriberId, userId, tenantId. Tables: SUBSCRIBER (soft delete, IS_ACTIVE). Response: void.

POST GetSubscriberDetails

  • Payload: SubscriberSearchCriteria — SubscriberID, EmailAddress, SmsAddress, Category, IsActive, TenantId.
  • Tables: SUBSCRIBER (READ). Response: 200 Ok List<Subscription>.

POST SearchSubscriberDetails · GetSubscriberEmailDetails · GetSubscriberSMSDetails

  • SearchSubscriberDetails: payload SubscriberQuery → TryRoute; SUBSCRIBER READ → 200 Ok SubscriberQuery.
  • GetSubscriberEmailDetails: payload tenantId; SUBSCRIBER READ → List<SubscriberEmailDetails>.
  • GetSubscriberSMSDetails: no param; SUBSCRIBER READ → List<SubscriberSMSDetails>.

3D. Subscriptions (link subscriber ↔ event)

POST CreateSubscription

  • Purpose: Subscribe a subscriber to an event (with SendSMSMessage flag).
  • Payload: Subscription — EventID, SubscriberID, EMail, SmsAddress, SendSMSMessage (bool), Subsystem, EventNameContains, Category, TenantId.
  • Operation: CreateSubscriptionBusiness(request).Execute() → CreateSubscriptionDataAccess.
  • Tables: EVENT_SUBSCRIPTION (INSERT). Response: 200 Ok Subscription (SubscriptionId populated).

POST GetSubscriptions · UpdateSubscription · SearchEventSubscriptions

  • GetSubscriptions: payload SubscriptionSearchCriteria → GetSubscriptionBusiness; EVENT_SUBSCRIPTION + SUBSCRIBER + EVENT (3-way JOIN READ) → List<Subscription>.
  • UpdateSubscription: EVENT_SUBSCRIPTION (UPDATE) → 200 Ok Subscription.
  • SearchEventSubscriptions: payload SubscriptionQuery → TryRoute; EVENT_SUBSCRIPTION (+joins) READ → SubscriptionQuery.

3E. Notifications (the send operations)

POST SendEmail

  • Purpose: Send an on-demand email (used standalone and by SendAndPostSubscribedEvent).
  • Payload: SendMailRequestParams — TenantId, Subject, MailBody, Priority (MailPriority=Normal), AddressList (List<Address>), FromAddress (Address?), AttachmentList (List<Attachments>?).
    • Address: EmailAddress, DisplayName, MailType (To/CC/Bcc).
    • Attachments: Name, ContentId, Contents (byte[]), AttachmentType (PlainText/HTML/Jpeg/Pdf/…).
  • Operation: allowed-domain filter → InitializeAppConfigManager(tenantId) → Library.Business.NotificationService().SendNotification(...) → SMTP send → write audit.
  • Tables: NOTIFICATION_AUDIT + RECEIVER_AUDIT (INSERT). Also SMTP server.
  • Response: void (200/204). Failure → FaultException<ServiceException> + audit row with null sent-time.

SOAP ONLY SendSmsText — not exposed via REST

  • Present on the WCF INotificationService contract and NotificationService.cs, but no [HttpPost] action in NotificationServiceController. Reachable only over SOAP.
  • Sends via the HTTPS SMS gateway and writes NOTIFICATION_AUDIT / RECEIVER_AUDIT.

6. Key Takeaways for a Newcomer

  1. One controller, ~22 POST endpoints, grouped as Events, Occurrences, Subscribers, Subscriptions, Sends.
  2. No API-level auth today — add authentication/authorization in any modernization. UseAuthorization() alone does nothing here.
  3. tenantId is mandatory on write/send operations (throws if missing) and drives per-tenant config loading.
  4. Reads return lists/query objects; writes echo the saved DTO; deletes are soft (IS_ACTIVE); sends return void and always write the two audit tables.
  5. SendSmsText is not in the REST API — SOAP only.
  6. All failures surface as FaultException<ServiceException> translated by ApiExceptionHandlingMiddleware.
Security priority: the API has no authentication/authorization. Before any external exposure or modernization, add an authentication scheme (JWT/OAuth or API key) and [Authorize] policies, and move the tenant check behind it.
