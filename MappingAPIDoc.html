SOAP → REST Mapping

Notification subsystem WCF operations mapped to a .NET 10 REST API

Generated 2026-11-04 · Source: INotificationService + Query/Command/Event contracts

Scope: All operations across the four WCF services — 23 on INotificationService, plus GetEvents (query service), AddEvent (command service), and the event-distribution service — mapped to REST routes for a .NET 10 API.

1. Guiding Principles

  • Reads → GET, creates → POST, updates → PUT, deletes → DELETE (current code makes everything POST).
  • Group by resource (events, subscribers, subscriptions, notifications) instead of four separate SOAP services.
  • tenantId moves to a header (X-Tenant-Id) or route prefix, not a body/query param on every call.
  • "Search" operations (rich query objects) stay POST .../search because they carry complex filter bodies.

These two matter most for the modernization — they map cleanly to the MailKit email sender and the MailKit email-to-SMS sender.

8. Event Distribution — NOT a REST Endpoint

/NotificationEventService (IEventDistribution) is internal event-sourcing plumbing, not a public API. In .NET 10 you would replace it with a message broker / event bus (e.g. Azure Service Bus, RabbitMQ) or in-process domain events — services publish/subscribe instead of calling a SOAP endpoint. Do not expose it as REST.

11. Notes on the Translation

  • CQRS preserved: write endpoints (POST/PUT/DELETE) route to command handlers; GET and /search route to query handlers — same TryRoute idea, behind REST.
  • tenantId repeated in nearly every SOAP operation becomes a single X-Tenant-Id header + middleware that calls the per-tenant config load (today's InitializeAppConfigManager(tenantId)).
  • Fault contracts (ServiceException) become standard HTTP problem responses (400/404/500 with a problem-details body).
  • Search vs filter: simple reads use query-string GET; the rich *Query objects keep a POST .../search body.
Bottom line: four SOAP services collapse into four REST resource groups plus a messaging replacement for event distribution — with proper HTTP verbs, header-based tenancy, and CQRS preserved behind the endpoints.
